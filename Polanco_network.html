DATA AND METHOD

How to read this network

The network shows relationships recorded in Copy of Polanco_21_10 · Sheet1. The snapshot from 21 October 2026 contains 334 data rows (rows 2–335). This self-contained HTML file works offline; table links require access to Google Sheets.

Nodes and connections

Each distinct identifier represents one node. The 334 records are grouped into 115 ordered pairs between 116 nodes. Arrows run from the subject in Jesuit ID to the entity in entity mentioned ID; the original description defines the relationship, including passive phrasing. Line width represents the number of rows for that pair, rather than independent historical confirmations.

Data structure

Juan Alfonso de Polanco is the subject of every row. This is an ego network with a star structure. The table contains no separate relationships between the other entities; none have been inferred from descriptions or shared neighbours. The central node remains visible when filters are applied.

Metrics from the reference code

From Monumenta_Indica.py, the implementation uses weight aggregation, degree, weighted degree, PageRank, Louvain and Sigma export. Explicit relationships in this dataset replace page co-occurrences. As in the reference, metrics use an undirected, weighted projection of the full network. Arrows in this view help interpret the table rows. The force-directed layout and Louvain use random seed 42. The layout uses unweighted topology to separate labels; line width shows the weights.

Identity and data quality

Three IDs have inconsistent entity types: P80 (Society of Jesus), P257 and P262 (Roman Curia) are recorded as both institution and person. The view uses the most frequent type per ID; ties use the first table entry. For these three IDs, the resulting type is institution. Each row’s original type is preserved in CSV, JSON and relationship details.

Identical names assigned to different IDs have been kept separate: they may represent different people or require manual review. These labels include the ID. Uncertain statements marked with a question mark remain unresolved.

In the genealogical section (rows 254–335), values in generation appear to be dates, while values in dates appear to be notes. The original fields are preserved without shifting them automatically and are available in each relationship’s details. The relation_basis field is empty in 252 rows; the “Not specified” filter does not imply a missing relationship.

Controls and export

Search covers names, IDs, descriptions, sources and additional fields. Selecting a result zooms to its node. Click the background or press Escape to clear the selection. Labels can be shown for all nodes. CSV exports the currently visible rows with their original columns and row numbers. JSON contains the full dataset and metadata; filters do not recalculate centrality.
